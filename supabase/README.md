# Supabase civics banks

The dedicated project contains exactly two public-schema question tables. They
remain inaccessible to direct `anon`/`authenticated` table queries. The local
MVP exposes questions through a narrow allowlisted RPC and stores minimal
anonymous progress in one private `game_private.sessions` table.

| Table | Filing cohort | Questions | Geography-resolved rows |
| --- | --- | ---: | ---: |
| `civics_questions_2008` | N-400 filed before October 20, 2025 | 100 | 705 |
| `civics_questions_2025` | N-400 filed on or after October 20, 2025 | 128 | 733 |

One row represents one question in one applicable geography. The composite key
is `(question_number, geography)`; repeating a question for another jurisdiction
does not create an additional question in a selected practice bank.

## Geography and selection

- `geography = 'US'`: national answer.
- `geography = 'US-CA'`: state/territory answer (California is an example).
- `geography = 'US-CA-12'`: congressional-district answer.
- `state_code` and `district_code` preserve the corresponding canonical codes.
- `geographic_scope` and generated `is_geography_dependent` explain the context.
- `is_time_dependent` is an editorial current-officeholder/composition/calendar
  flag. False is not a guarantee that a fact can never change.

Choose the table from the N-400 filing date, then parameterize the three relevant
geography values. Example using an arbitrary California district:

```sql
select question_number, question_text, answers, answer_display,
       answer_updated_on, next_update_on
from public.civics_questions_2025
where geography in ('US', 'US-CA', 'US-CA-12')
order by question_number;
```

This returns 128 distinct questions. The corresponding older table returns 100.
All 441 supported district selections were checked. Do not query all House
districts in a state and silently choose a representative. Resolve the district,
or select an at-large/nonvoting entry when it is the only one for the jurisdiction.

## Answers, dates and vacancies

`answers` contains canonical response options. `answer_display` carries readable
display text; for a vacancy this is `Vacant (previously: NAME)`.
`previous_officeholder` is display metadata, never an accepted current name.
Current vacancies are FL20 and TX23. The game may localize the display to
`Vacant (previously: NAME)`.

`answer_updated_on` retains the source-reviewed dataset date, currently
**2026-10-27**. `next_update_on` is generated by adding **one calendar month**,
currently **2026-11-27**. `imported_at` is the actual database insertion time and
does not establish factual freshness. Future seed imports preserve the catalog's
review date instead of advancing it merely because an import ran.

`regular_transition_on` is separate informative metadata. Neither it nor the next
maintenance date is a guaranteed factual expiration. No cron/updater is enabled.
The [internal change guide](CHANGE_GUIDANCE.md) now adds nullable expected dates
or windows, per-answer timelines and a private live `possibly_outdated` signal.
Sources and their publication/verification metadata are retained in `source_urls`
and `source_details`; `notes` preserves relevant context.

The local UI displays an unofficial-tool notice, asks for the filing cohort and
applicable jurisdiction, and shows a per-question information bubble for five
seconds before fading. It reveals official English questions and answer choices;
it does not translate or grade free-form answers.

## Access and verification

RLS is enabled on both question tables and the private session table. All direct
question-table privileges are revoked from `PUBLIC`, `anon`, and
`authenticated`. Only the five exact anonymous public RPCs are executable by
`anon`; authenticated execution is revoked. The session table also has an
explicit `USING (false)` / `WITH CHECK (false)` policy. The unexposed
`game_private` schema grants `anon` usage and execute only on capability helpers
called by the invoker wrappers; it grants no direct session-table access.

`get_practice_questions` returns only question number/text/section, official
answers and display, answer review/next-review dates, source URLs, and two
geography/time dependency flags. It does not expose `change_guidance`, expected
change windows, review flags, notes, or session identifiers. Internal
`civics_answer_review` remains private.

`create_game_session`, `resume_game_session`, `record_quiz_check`, and
`record_card_review` take a cryptographically random 43-character recovery code
as a bearer capability. The database stores only its SHA-256 verifier. Session
updates validate that capability and the 168-hour boundary atomically; wrong
codes do not update activity. The RPC returns no UUID or verifier. Progress
contains only cumulative attempts/correct answers/cards reviewed and the cohort
and jurisdiction selector needed to restore the correct question bank.

The scheduled job `citizenship-prep-expired-sessions` is active at minute 17 of
each hour. Access is rejected exactly at 168 hours; physical active-row deletion
occurs at the next hourly run (up to about 60 minutes after rejection). This is
separate from monthly civics-data review. Backup, provider request-log retention,
and public-launch abuse controls still need deployment review.

The old automatic-RLS function's excess client EXECUTE privileges were revoked
without changing its definition or disabling the event trigger. A rolled-back
table probe verified that automatic RLS still works. The security advisor
returned zero notices after the migration/import.

Verification covered counts, all geography selectors, source-to-database core
content fingerprints, generated month-end dates, invalid geography/vacancy/number
constraints, actual client-role denial, and RLS denial under temporary grants.
The MVP SQL verifier passed independently in a transaction and rolled back its
probe sessions. Core fingerprints remain `2c79ad56f1b2df4ad1be60e32fd5e405`
(2008) and `3072b66de54693a8359fe9131ea3fa54` (2025). The security advisor
returned zero lints; performance reports only the new TTL index as unused while
the session table is nearly empty. A publishable URL/key is configured only in
ignored local `.env.local`; no service/secret key was retrieved or committed.
Local files remain uncommitted/unpublished; Vercel remains untouched.
